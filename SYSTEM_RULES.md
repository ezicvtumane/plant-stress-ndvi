# ТЕХНИЧЕСКИЙ РЕГЛАМЕНТ И СИСТЕМНЫЕ ИНВАРИАНТЫ ПРОЕКТА
**Проект:** `plant-stress-ndvi` (Всероссийский конкурс научно-технологических проектов «Большие вызовы», трек «Агропромышленные и биотехнологии»)  
**Аппаратная платформа:** Одноплатный компьютер Orange Pi 4 Pro (Armbian Linux / aarch64), NoIR-камера со спектральным стробированием (660/850 нм), тепловизор UNI-T UTi120S, АЦП ADS1115 (I2C-0), датчик микроклимата Sensirion SHT30, беспроводной BLE-термогигрометр Xiaomi.

## 1. БИОЛОГИЧЕСКИЕ И АППАРАТНЫЕ ИНВАРИАНТЫ (НЕ НАРУШАТЬ)

### 1.1. Строгая топология когорт (Единый синхронный опыт, посев 29.09.2026, $n = 45$):
- **Когорта №1 (К1):** 🌱 **Контроль** (100% ПВ) | Вход в боксе: разъём `A0` (быстросъем) | Регулярный полив 15–20 мл/сут
- **Когорта №2 (К2):** 🧂 **Осмос** (СТРОГО 100 мМ NaCl) | Вход в боксе: разъём `A0` (быстросъем) | **СТРОГО отдельный поддон-изолятор**
- **Когорта №3 (К3):** 🔴 **Терминальная засуха** (Контроль гибели, 96+ ч без воды) | Вход в боксе: разъём `A0` (быстросъем) | Оцифровка точки невозврата
- **Когорта №4 (К4):** 🟡 **Превенция** (Ранний полив по маркеру $\Delta T > +0.8^\circ\text{C}$ при высоком $NDVI \approx 0.75\text{--}0.80$) | **Датчик почвы: ОТСУТСТВУЕТ** (Ground Truth: лабораторные весы)
- **Когорта №5 (К5):** 🔵 **Реакция** (Традиционный визуальный контроль, полив только при явном поникании листьев) | **Датчик почвы: ОТСУТСТВУЕТ** (Ground Truth: лабораторные весы)
- **Стенд №0 (К6):** 🎯 **Калибровочный стенд** (Посев 22.09.2026, $n = 9$) — предварительный стенд юстировки оптики и OCR

### 1.2. Концентрация соли:
- Использовать **ИСКЛЮЧИТЕЛЬНО 100 мМ NaCl**. Горох (*Pisum sativum L.*) — типичный гликофит.
- Категорически запрещено возвращать в коде, комментариях, UI, презентациях и документации значение «150 мМ». Единственное вхождение числа 150 в репозитории — габаритный размер корпуса `150 x 150 мм` в `scripts/cad/generate_laser_box.py`.

### 1.3. Логика датчиков почвы (ADS1115):
- Емкостные датчики влажности v1.2 физически смонтированы в кассетах К1, К2 и К3.
- В измерительном боксе смонтирован **единственный быстросъемный разъем**, выведенный на вход **A0** АЦП ADS1115. При установке кассет К1, К2 или К3 их встроенный датчик подключается к этому разъему A0. Каналы A1..A3 зарезервированы / подтянуты к GND.
- В кассетах К4 и К5 датчики не устанавливаются (водный баланс отслеживается гравиметрически на весах). В журналах указывать `--` или `N/A`.
- В калибровочных константах АЦП строго зафиксирован стандарт двухточечной градуировки в торфе при 3.3В питании:
  - $V_{\text{сух}} = 2.072\text{ В}$ (воздушно-сухой торфяной субстрат в кассете / сухой датчик, 0.0% ПВ);
  - $V_{\text{100% ПВ}} = 1.923\text{ В}$ (полная влагоемкость торфа, экстраполяция от реперной точки 70% ПВ при $1.968\text{ В}$, $\Delta V = 0.149\text{ В}$).
- Для агрономического расчета влажности субстрата $W_{\text{soil}}$ используется единая функция:
  $$W_{\text{soil}} = \max\left(0.0,\ \min\left(100.0,\ \frac{2.072 - V_{\text{soil}}}{0.149} \times 100\%\right)\right)$$

### 1.4. Физиологический триггер превенции (Маркер устьичного замыкания):
- Когорта К4 поливается по критерию $\Delta T = T_{\text{leaf}} - T_{\text{air}} > +0.8^\circ\text{C}$.
- Вегетационный индекс NDVI в этот момент **ДОЛЖЕН БЫТЬ ВЫСОКИМ** ($NDVI \approx 0.75\text{--}0.80$). Ожидание падения NDVI для полива является грубой методологической ошибкой, так как оптическая деградация хлорофилла наступает на 36–48 часов позже температурного перегрева листа.

### 1.5. Регламент полива когорты К4 («Превенция»):
- Полив К4 производится строго при фиксации $\Delta T > +0.8^\circ\text{C}$.
- Объем превентивного полива рассчитывается строго гравиметрически: объем компенсирует накопленную убыль массы от 1-го дня (День 1: $297.0\text{ г} \to$ День 5: $246.8\text{ г}$, суммарная потеря $50.2\text{ г}$). Доза: **4 мл отстоянной воды в каждую из 9 ячеек** (суммарно $36\text{ мл}$ на кассету).
- Кассеты К3 («Засуха») и К5 («Реакция») в момент срабатывания алерта **строго остаются без полива**, несмотря на сигнал станции, в соответствии с протоколом сравнительного анализа стратегий.

## 2. ТРЕБОВАНИЯ К СЕРВЕРНОМУ КОДУ (web_station.py и src/)

### 2.1. Исключение фиктивных функций, NameError и Fail-Safe микроклимата:
- Запрещено использовать удаленные модули (например, `read_xiaomi_climate()`).
- Опрос климата Sensirion SHT30 производить через внутренний синхронный метод `_read_climate_sync()` или `read_climate_async()`.
- Все пути к служебным папкам (`DOCS_DIR`, `STATIC_DIR`, `DATA_DIR`) должны быть явно определены в блоке конфигурации через `BASE_DIR`.
- При обработке словаря беспроводного датчика подоконника (`get_windowsill_climate()`) обязательна строгая проверка на `None`: ключи `t_c` и `rh_pct` могут возвращать `None`. Запрещены прямые сравнения вида `val > 0` без предварительного `val is not None`.
- При отсутствии связи с внешним BLE-датчиком сервер обязан бесшовно и без исключений подставлять показания внутреннего датчика оптического бокса Sensirion SHT30 (`_read_climate_sync()`).

### 2.2. Защита асинхронного Event Loop и автовосстановление I2C:
- Любые обращения к шине I2C (`smbus2`, ADS1115, SHT30) должны выполняться через выделенный `i2c_executor = ThreadPoolExecutor(max_workers=1)`, чтобы исключить коллизии на шине `/dev/i2c-0` и блокировку Uvicorn.
- При возникновении исключений `[Errno 62] Timer expired` или `[Errno 16] Device or resource busy` на шине `/dev/i2c-0` модуль обязан вызвать функцию сброса `recover_i2c_bus()` через sysfs unbind/bind платформенного драйвера:
  ```bash
  echo 2510000.twi > /sys/bus/platform/drivers/sunxi-twi/unbind
  echo 2510000.twi > /sys/bus/platform/drivers/sunxi-twi/bind
  ```

### 2.3. Сетевые привязки веб-сервера:
- Сервер FastAPI/Uvicorn обязан слушать хост `0.0.0.0` на порту `8000`.
- Запрещено жестко привязывать хост к конкретному IP (например, `192.168.0.x`), так как станция должна отвечать одновременно в автономной сети точки доступа `192.168.4.1` и в локальной кабельной сети `192.168.0.x`.

### 2.4. Чистота импортов и синтаксиса:
- Следить за отсутствием дублирующихся строк импорта (например, повторный импорт `Jinja2Templates` и роутеров).

### 2.5. Атомарное двойное зеркалирование журналов замеров:
- Любое внесение или корректировка данных (`handle_update_measurement`, сохранение пакетного замера) обязаны вносить синхронные изменения в **ОБА** файла:
  1) Глобальный журнал: `data/measurements.csv`
  2) Журнал активной серии: `data/experiments/<active_id>/measurements.csv`
- Недопустима рассинхронизация между глобальным реестром и папкой активного эксперимента.

### 3.2. Корректность синтаксиса, названий и кодировки:
- Следить за отсутствием опечаток в именах файлов: `ndvi_processor.py` (не `dvi_processor.py`), `numpy` (не `umpy`), `asyncio` (не битые байты).
- Все файлы документации (`.md`, `.html`, `.json`) сохранять строго в кодировке **UTF-8 без BOM**.
- Проверять наличие знаков `%` во всех формулах и таблицах (например, `> 75%`, `> 75%`).
- Формулы пересчета напряжения АЦП оформлять в читаемом виде: `V_soil = 2.072 - (Pct / 100) * 0.149`.

### 3.3. Разграничение Стенда №0 и хроники эксперимента:
- Любые ссылки на законченные кривые гибели и триптихи сопровождать обязательным примечанием, что они получены на калибровочном стенде №0 (посев 22.09.2026), а основной 5-когортный опыт (`exp_1791463544`, посев 29.09.2026) находится в динамике.

## 4. ПРАВИЛА РАБОТЫ С СИСТЕМОЙ И АВТОНОМНЫМ WI-FI

### 4.1. Автономный режим точки доступа (AP PlantStation):
- Не модифицировать системные файлы `/etc/NetworkManager/` и `/etc/dnsmasq*`, если это прямо не требуется задачей.
- Адрес станции в автономной сети — `192.168.4.1`, а пул DHCP раздает адреса `192.168.4.X`.
- При подключении клиентского ПК под Windows к автономной точке без интернета ОС может присвоить сети категорию `Public`, что приводит к блокировке входящих ответов брандмауэром (`WinError 10054 / ConnectionReset`). Профиль соединения на Windows-клиенте должен быть переведен в доверенную категорию `Private`:
  ```powershell
  Set-NetConnectionProfile -InterfaceAlias <Имя_Адаптера> -NetworkCategory Private
  ```
- При задержках DHCP на клиенте разрешено использовать статический IP: `192.168.4.189/24` (без установки флага шлюза по умолчанию, чтобы не разрывать основной интернет-кабель Ethernet).

### 4.2. Безопасность GPIO, реле и стробирования:
- Управление стробированием NoIR ведется строго через модуль `hardware/hal` или линии `PL4` (Red 660 нм) и `PL7` (NIR 850 нм).
- Длительность импульса стробирования светодиодов не должна превышать **200–300 мс** на кадр. Постоянное включение реле категорически запрещено во избежание перегрева кристаллов и паразитной тепловой засветки для тепловизора UTi120S.

## 5. ПРОТОКОЛ ПРОВЕРКИ И GIT-КОНТРОЛЯ

Контрольный инженерный чек-лист перед фиксацией изменений:
1. **Синтаксическая валидация Python-скриптов:**
   ```bash
   python3 -m py_compile web_station.py
   ```
2. **Проверка службы (если затрагивался сервер/рантайм):**
   ```bash
   sudo systemctl restart plant-station.service && systemctl is-active plant-station.service
   ```
3. **Защита целостности базы Git-объектов:**
   Перед коммитом очищать 0-байтовые объекты, возникающие при аварийном обесточивании:
   ```bash
   find .git/objects/ -type f -size 0 -delete
   ```
4. **Проверка `git status` и `git diff`:**
   Убедиться в отсутствии мусорных файлов, нежелательных правок или захардкоженных временных путей.
5. **Фиксация и пуш в ветку `main`:**
   ```bash
   git add <files> && git commit -m "<четкое описание>" && git push origin main
   ```
